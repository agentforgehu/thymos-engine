# 事实、抽取、情绪与意图：四项修复的本地复测

> 版本：0.3.0 工作区（Unreleased）  
> 日期：2026-11-13  
> 模型：本地 `llama-server` + `qwen3.6-35b-a3b`（Q4_K_M）  
> 条件：30 轮连续对话，`max_chars=300`，`top_k=5`，同一状态、同一提示词；10 个探针。

这轮不是再加一层功能，而是修四个会直接毁掉体验的规则问题：事实块不按问题裁剪、中文事实抽取太窄、情绪标签塌缩、纯事实问句被误判为 `mixed`。

---

## 1. 事实块：从“全量档案”改成“按问题取一条”

### 问题

30 轮后事实库只有 4–5 条，但问“他叫什么”和问“他的项目叫什么”，返回的事实块几乎一样；在 300 字符预算下，事实块占掉大半，情景记忆被挤掉。

### 修复

`FactStore.match_predicates()` 现在只返回查询真正命中的谓词：

- `他叫什么` → 只给 `姓名`；
- `他的项目叫什么` → 只给 `项目`，不再附带 `姓名`；
- `他做什么工作` → 只给 `职业`，不再因为“工作”同时命中 `项目`；
- 没有命中任何谓词时，只给一条 `其他已知：现居、项目、职业（未展开）`，不再展开值。

姓名只在被明确询问时作为锚点；`我叫什么，对什么过敏` 仍会同时保留姓名和过敏，不会因为“去锚点”误删。

### 300 字符预算下的实测

用 13 条事实的固定回放，事实块上限为 `300 × 0.35 = 105` 字符：

| 查询 | 事实块字符 | 占 300 字符 |
|---|---:|---:|
| 他叫什么？ | 42 | 14% |
| 他的项目叫什么？ | 47 | 16% |
| 他做什么工作？ | 45 | 15% |
| 今天天气怎么样？ | 66 | 22% |

修复前同类查询会把姓名、现居、项目、职业、过敏等多行一起倒出；修复后事实块稳定在 14–22%，剩余预算留给情景记忆。

对应回归：`tests/test_fact_relevance.py::test_small_budget_fact_block_is_query_specific`、`test_unmatched_query_gets_one_line_digest_not_full_dump`。

## 2. 中文事实抽取：补上“从…来/做…/项目叫/我妹/不要”

### 新增可抽取句式

| 输入 | 抽取结果 |
|---|---|
| `我从恩施来上海，做软件。` | `city=上海`、`hometown=恩施`、`job=软件` |
| `他的项目叫 piko。` | `project=piko` |
| `我妹下个月结婚。` | `family=妹`、`family_event=我妹下个月结婚` |
| `香菜不要。` | `food_dislike=香菜` |
| `今天吃火锅，晚上去看牙。` | `food_event=火锅`、`health_event=看牙` |

关键点不是“多写几个正则”，而是把**已知事实**和**事件时间**分开：

- “我妹下个月结婚”是现在就知道的家事，不能因为事件在 30 天后才发生，就在今天查不到；`family_event` 立即生效，时间表达保留在值里。
- “我搬到上海”仍是未来生效，旧城市在上海生效前保持当前值；这条原有语义没有被破坏。

README 已新增[“支持的中文事实句式”](../README.md#支持的中文事实句式)表，明确列出当前覆盖范围，避免把规则抽取器宣传成通用中文 IE。

对应回归：`tests/test_fact_relevance.py::test_chinese_third_person_and_event_patterns`、`test_family_query_does_not_fall_back_to_city`。

## 3. 情绪标签：不再 30 轮里 28 轮“期待”

### 问题

旧版 `goal_relevance` 随句子长度饱和，且评价词典对“被夸 / 被骂 / 被关心”几乎没有区分；结果 30 轮日常对话里 28 轮判成 `anticipation`，压力一路涨到 0.83。

### 修复

- `goal_relevance` 不再用句子长度做主要项：长度项封顶 32 字符，疑问句再打 0.72 折；中性事实的 relevance 明显下降。
- 增加三类社交评价线索：
  - 夸奖 / 认可 → `agency=other`，偏正向，典型 `joy`；
  - 责骂 / 嘲讽 / 冷落 → `agency=other`、控制感偏高、规范值为负，典型 `anger`；
  - 关心 / 照顾 / 安慰 → `agency=other`、规范值为正，典型 `trust`。
- 关心可以和安全事件共存：“我生病了，朋友一直关心我”不再因为“病”这个词抵消成 `neutral`。

### 30 轮实测标签分布

| 标签 | 轮数 |
|---|---:|
| neutral | 16 |
| sadness | 7 |
| excitement | 2 |
| anticipation | 2 |
| joy | 2 |
| anxiety | 1 |

压力范围 **0.098–0.168**（旧版峰值 0.83），皮质醇 **0.34–0.64**；没有出现单一标签支配整段对话。

对应回归：`tests/test_appraisal.py::test_praise_insult_and_care_have_distinct_labels`、`test_relevance_is_not_saturated_by_sentence_length`。

## 4. 意图分类：纯事实问句不再落到 `mixed`

### 问题

`他住哪`、`他叫什么` 这类第三人称纯事实问句没有命中旧 `_FACTUAL` 规则，落到“无显式线索”的 `mixed`，于是多跑一次情景召回、浪费预算。

### 修复

补入 `叫什么`、`住哪`、`住哪儿`、`哪座城市`、`做什么工作`、`干什么`、`职业`、`老家`、`家乡`、`妹妹`、`结婚` 等事实谓词。现在：

| 查询 | 修复前 | 修复后 |
|---|---|---|
| 他住哪？ | mixed | factual |
| 他的项目叫什么？ | factual | factual |
| 他叫什么？ | mixed | factual |
| 他做什么工作？ | factual | factual |
| 我今天有点累，他住哪？ | affective | mixed |

最后一条仍保留 `mixed`：它确实同时有情绪和事实需求，不应被一刀切成 `factual`。

对应回归：`tests/test_policy_intent.py`。

## 复现

```bash
# 通用写法：把两个路径换成你本机的 llama-server 与 GGUF
python experiments/run_local_50.py \
  --exe /path/to/llama-server \
  --model /path/to/model.gguf \
  --turns 30 \
  --max-chars 300
```

输出：

- `.work/longrun/report.json`：逐轮状态、意图、门控、探针结果；
- `.work/longrun/report.md`：可读报告。

## 仍然不够好的地方

1. **规则抽取仍是保守兜底。** 这轮补的是高价值句式，不是通用中文 IE；复杂从句、指代、否定嵌套仍会漏。生产环境应接 `LLMFactExtractor`，并用本文件的句式做回归。
2. **情绪标签仍是词典 + 规则。** 这轮解决的是“明显事件不再塌缩”，不是“情绪识别准确率”。反讽、混合情绪、文化差异仍会错。
3. **30 轮不是统计证据。** 它只能证明管线在固定剧本上不崩；要证明“比基线好”，需要同一 LLM、同一 prompt、同一预算下的 A/B，以及 held-out 多会话评测。
4. **事实块占比是固定回放测量。** 13 条事实、300 字符预算下的 14–22% 不代表所有真实对话；真实长文事实值会更长，仍受 35% 硬上限保护。
