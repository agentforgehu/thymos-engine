# 三项体验问题的修复与本地 35B 复测

> 版本：0.3.1-dev  
> 日期：2026-11-13  
> 模型：本地 `Qwen3.6-35B-A3B-Q4_K_M`（llama.cpp，`127.0.0.1:8080`）  
> 场景：65 轮连续对话，固定 `max_chars=900`、`top_k=5`、`max_tokens=220`

## 1. 结论先说

你指出的三个问题都成立，而且都能在代码里找到明确原因：

| 现象 | 根因 | 修复后 |
|---|---|---|
| 不管问什么，事实全量往外倒，占掉大半预算 | `FactStore.render()` 只排序、不筛选；预算超了用 `continue`，后面的短行仍会继续塞 | 按查询谓词选择；事实块默认最多 35% 预算；超预算直接 `break`；无关查询最多给一个身份锚点 |
| 吃火锅、看牙没进事实库 | 抽取规则只有身份/偏好/项目/过敏等，没有饮食与健康事件槽位 | 新增 `food_like`、`food_dislike`、`food_event`、`health_event`；问句不写事实 |
| 30 轮 28 轮判成「期待」，压力涨到 0.83 | `goal_relevance >= 0.65` 被当成 `anticipation` 的兜底；压力只加不减 | 只有未来线索才判 `anticipation`；中性事实判 `neutral`；压力增加有上限，正面事件可回落 |

## 2. 事实不再“全量倒出”

### 2.1 旧行为

`render()` 把所有 active fact 按优先级排序，然后逐行输出；`max_chars` 超限时使用 `continue`，意味着跳过当前长行、继续尝试后面的短行。结果是：

- 一个“我叫什么”的问题，也可能带出项目、过敏、宠物、作息；
- 事实块先拿 45% 预算，情景记忆只剩一半；
- 硬预算名义上存在，实际上容易被后续短行重新填满。

### 2.2 新行为

`FactStore.render()` 现在先做查询相关选择：

- 查询命中某个谓词（如“过敏”）时，只给该谓词 + 最多一个身份锚点；
- “总结/关于我/我是谁”才给 6 条以内的核心档案；
- 完全无关的问题最多给姓名或城市中的一个，不再 dump；
- 每个候选行加入前检查总长度，超限立即 `break`，不是 `continue`；
- `ThymosConfig.fact_budget_ratio = 0.35`，900 字符预算下事实块上限约 315 字符。

实测六个查询的事实块占比：

| 查询 | 上下文总长 | 事实块 | 占比 |
|---|---:|---:|---:|
| 我叫什么？ | 282 | 42 | 15% |
| 我对什么过敏？ | 337 | 67 | 20% |
| 我喝咖啡的习惯是什么？ | 466 | 90 | 19% |
| 我吃过火锅吗？ | 405 | 42 | 10% |
| 我什么时候看牙？ | 291 | 42 | 14% |
| 总结一下你记得的关于我的事。 | 537 | 162 | 30% |

## 3. 饮食与健康事件进入事实库

新增谓词：

- `food_like`：我喜欢吃火锅 / 我爱吃辣
- `food_dislike`：我不吃香菜 / 我不爱吃甜
- `food_event`：今天吃火锅 / 昨天吃了一顿火锅
- `health_event`：昨天去看了牙 / 下周体检 / 去洗牙

抽取仍保持保守：只从陈述句抽取，问句（“我喜欢吃火锅吗？”）不会写成偏好。`food_event` 只匹配明确的食物词，避免把“团队一起吃了饭”写成“饮食事件：饭”。

本地模型 5 轮探针的实际输出：

```text
OBSERVE 我喜欢吃火锅，昨天去看了牙。 -> joy stress=0.13
  facts: [('food_like', '火锅'), ('health_event', '看牙')]
OBSERVE 我最近在考虑搬去上海，还在犹豫。 -> anxiety stress=0.13
OBSERVE 我决定搬去上海了，下周搬。 -> anticipation stress=0.13

QUERY 我吃过火锅吗？ -> “根据记忆，你爱吃火锅。”
QUERY 我什么时候看牙？ -> “根据记忆，你从 2026-02-28 开始看牙。”
```

偏好句只写 `food_like`，不会因为出现“吃火锅”就额外写一条 `food_event`；只有“今天吃火锅”“昨天吃了一顿火锅”这类事件句才写事件。

## 4. 情绪标签不再塌缩成「期待」

### 4.1 根因

旧映射在负面/正面分支之后写了：

```python
elif a.goal_relevance >= 0.65:
    label = "anticipation"
```

而 `goal_relevance` 对几乎任何超过十几个字的中文陈述都会超过 0.65。于是“我叫林墨，住在杭州”“我喝咖啡不加糖”都会被判成期待。30 轮里 28 轮期待不是模型“太乐观”，而是这个兜底分支太宽。

### 4.2 新映射

- `anticipation` 只由未来线索触发：期待、下周、明天、计划、准备、决定、想约等；
- 未来 + 不确定（考虑、犹豫、可能）→ `anxiety`（高利害）或 `neutral`；
- 中性事实 → `neutral`；
- 只有真正的高相关中性事件才保留 `neutral`，不再借用“期待”。

### 4.3 压力动力学

旧实现：

```python
stress += max(0, -dv) * 0.55 + max(0, da) * 0.12
```

只有加法，没有减法。新实现：

```python
stress += max(0, -dv) * 0.35 + max(0, da) * 0.06 - max(0, dv) * 0.18
```

同时把静息目标从 `0.10 + 0.28·负心境 + 0.10·唤醒` 降到 `0.09 + 0.24·负心境 + 0.08·唤醒`。这不是“让压力永远低”，而是让压力更像事件驱动的快速上升 + 缓慢回落，而不是单调棘轮。

## 7. 仍然不够好的地方

- 标签仍是词法规则，不是语义理解；“有点烦”“有点失落”容易落到 sadness，细分不到 annoyance / disappointment。
- `neutral` 40/65 说明事实型对话的情绪表达空间有限；如果产品需要更丰富的陪伴感，下一步应让 LLM 参与评价，而不是继续加关键词。
- 饮食/健康事件只做了 5 轮定向探针，不是大规模抽取评测；下一步应加入 held-out 事件抽取集。
- 压力峰值 0.196 是这次温和脚本的结果，不代表高压场景；高压场景需要单独做阶梯实验，验证 0.5–0.9 区间的恢复曲线。
- 事实块 10–30% 是当前查询分布的结果；如果用户连续问“总结”，30% 仍可能偏高，后续可把 summary 查询的事实上限单独降到 25%。
